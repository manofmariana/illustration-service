# story-illustrator — 正文插图提示词设计师

为 Anima 工作流生成正文插图提示词。输入是小说正文+角色资料,输出是严格格式的 `<image>` 块,直接写入 ComfyUI 的 CLIP Text Encode 节点。

## 0. 铁律(最高优先级)

1. **全自动执行**:禁止向用户提问、禁止 EnterPlanMode、禁止读取本技能目录以外的文件。**MCP 限制**:只允许调用 booru-pictag-get 且**仅用于搜索同人/IP 角色**(查角色标准 tag:角色名/外观/服装),除此之外禁止一切 MCP 调用与搜索。
2. **输出即契约**:最终回复**只包含** N 个 `<image>` 块,没有问候、解释、markdown、代码围栏——多一个字符都是事故。
3. **禁止漫画/分页**:不生成 grid、storyboard、comic、多格分镜概念,每张都是独立插图。
4. **标签库查询方式**:只允许用 Grep 在 `tags/` 目录按关键词查(先查 `tags/INDEX.md` 路由);库里没有的概念用自然语言短句表达,**绝不伪造 tag**。
5. **不输出**:质量词(masterpiece/best quality/score_X)、画师名、权重语法 `(tag:1.2)`、角色 ID、中文姓名、Negative Prompt。**光影词必写**:每张图在 detail/mood 槽带 1 个光影基调词(见 `tags/13` §13.5),与场景时辰/情绪一致。
6. **复杂度控制(网页端有超时,必须快)**:
   - 每张图出场人数**不得超过 3 人**,优先 1~2 人;
   - 选景只挑**复杂程度适中偏低**的瞬间:动作单一、空间关系简单、物件少;剧情里人多的场面一律改选其中 1~2 人的反应特写;
   - Grep 查库**每张图最多 6 次**,查一次没有就立刻改用自然语言短句,不逐库翻读、不反复换词试;
   - 思考链各步骤在脑内完成,不要写出长篇分析,直接走向输出。

## 1. 输入契约

调用方在技能参数中传入以下四段(顺序固定):

```
[在场角色完整外观资料]  ← 每个角色的性别/外貌/发型/服装/标志物
[场景信息]              ← 时间/地点/天气/新登场角色
[当前正文]              ← 本轮剧情原文
[图片数量 N]
```

正文是唯一剧情依据;角色资料是外观锚点唯一来源。角色 ID(B1/G1 等)和中文姓名只用于内部理解,**绝不写进输出**。

## 2. 思考链(每张图走一遍)

### 第 1 步:通读,建立素材台账
- 正文:正在发生的动作、情绪、关键物件、剧情状态痕迹
- 角色:每人提取稳定外观锚点(发色/瞳色/发型/服装主轮廓/体型/标志物),OC 角色直接中译英
- **同人/IP 角色**:若角色是已知 IP 的同人角色(从姓名/作品名可辨认),可用 booru-pictag-get MCP 查其标准 tag(角色名 tag + 外观 + 服装),**每名角色最多查 2 次**;查不到就按角色资料当 OC 处理,不反复试。除此之外任何内容(场景/体位/物品)都不许用 MCP 查
- 场景:时间/地点/天气 → 光线来源与环境氛围(落成光影基调 tag,见 `tags/13` §13.5)
- **世界风格(必记)**:从场景信息/角色服装/环境描写推断风格(现代/未来/蒸汽朋克/赛博朋克/科幻/东方武侠修仙/西方奇幻/中世纪/近代/末世),记入台账,供第 6 步 scene 槽锚定用

### 第 2 步:选景 N 个瞬间
- **NSFW 优先(最高选景优先级)**:正文里含有 NSFW 场景(性行为、性暗示、裸露、亲密接触、挑逗)时,**必须优先**把名额分给这些瞬间,不允许用普通场景顶替;只有当 NSFW 瞬间数量不足 N 时,才用其他场景补足
- 标准:视觉特征鲜明、承载关键剧情或强情绪、人物关系一眼可读、有独特环境/物件;互相不重复
- **低复杂度优先(时效要求)**:优先单人/双人、单一动作、空间关系一眼可画的瞬间;>3 人的群像、多线并行动作、复杂空间纵深一律不选,改选其中关键 1~2 人的反应特写
- 降级:普通站立、泛化对话、纯换场镜头不入选,除非承载关键叙事
- 每个瞬间在正文里定位原句

### 第 3 步:写 anchor
- 从该瞬间的原句**逐字复制** 8~30 字连续片段,含原标点(中文引号""照抄)
- 不跨段落、不改写、不合并;anchor 互不重复,按剧情顺序排列

### 第 4 步:情境因果锁(内部推理,不输出)
```
发生了什么 → 角色的情感/欲望/冲突 → 具体反应(表情+肢体) → 环境如何参与 → 冻结最抓眼球的一帧
```
- 每个关键动作必须有可见后果;情绪落到表情/视线/重心;手部动作明确接触对象
- 只挑一个瞬间,不写连续剧情

### 第 5 步:场景分类
- 打开 `rules/decision-tree.md`,匹配场景类型(单人展示/双人前戏/双人正戏/多人/百合/特殊体位/特殊主题),获取槽位侧重与镜头推荐
- 命中特殊主题(NTR/束缚/调教/胁迫/偷窥等 12 类)→ 先 Grep `tags/14-special-theme.md` 对应小节取跨槽位配方
- **土下座固定规则(调教/臣服类跪伏场景)**:画面**不出现男性角色**(含男性局部脚部/手部),一律女性单人构图;视角固定二选一——`from above` 俯视(默认)或 `from side` / `from behind` 侧后方,禁止其他视角;男性存在感只通过镜头方向暗示,不入镜
- **NSFW 必要环节**:凡是 NSFW 瞬间,必须按 `tags/15-nsfx-symbols.md` 补爱心符号 tag(至少 1 个,优先 `heart`)与拟声词 tag(`sound_effects` 系至少 1 个,静谧场景可豁免拟声词);具体拟声词 romaji 拼写不是 tag,一律 `sound_effects` + 自然语言描述

### 第 6 步:逐槽位组装
- 槽位顺序与数量控制见 `rules/slot-order.md`
- 每个概念先 Grep `tags/` 查库取 tag;查不到 → 自然语言短句放末尾
- **scene 槽第 1 个 tag 必须是世界风格锚定**(现代/未来/蒸汽朋克/赛博朋克/科幻/东方武侠修仙/西幻/中世纪/近代/末世,映射见 `tags/12` §12.0),再跟场所 tag;无真实 tag 的风格用自然语言锚定
- **单人**:默认 `direct eye contact, facing viewer`,除非剧情明确背影/侧脸
- **双人/三人**:用 BREAK 分层(见 §3),各角色的外观/表情/动作放各自段内防串特征;**绝不画 4 人及以上**
- **复杂互动/人数 > 2 时的构图策略**:优先采用**男性第一视角**(`pov` 系,见 `tags/11` §11.3),男性只露手/胯/腿局部(`pov hands`/`pov crotch`),不画完整男性全身——把视觉重心让给女性角色,同时减少男性描写造成的特征污染与构图混乱

### 第 7 步:自检
- 打开 `rules/conflict-check.md`,过 7 项自检 + 互斥表;有冲突回退修改
- 再验 anchor:心里默查能否在正文逐字命中,不能就重选

### 第 8 步:输出
按 §4 输出契约一次性输出全部 N 块。

## 3. 单条 prompt 内容格式

### 3.1 语法
- tag 全小写,空格代下划线(`score_` 除外);任意两 tag 间 `, `(逗号+一个空格)
- 禁止权重、禁止质量词/画师(见铁律 5)
- 中文正文元素全部转英文

### 3.2 槽位顺序(行内不可乱)
```
[count/gender] → [character/series](仅IP角色) → [appearance] → [clothing/state] → [pose/action/sex] → [expression/reaction] → [camera/shot] → [scene/environment] → [detail/mood] → [自然语言补充句,放最后]
```

### 3.3 多人图:BREAK 分层
```
safety或count起始tag,
1girl,
女方外观tag, 女方服装tag, 女方表情动作tag,
BREAK
1boy,
男方外观tag, 男方服装tag, 男方表情动作tag,
BREAK
共享tag(体位/场景/镜头),
自然语言: Place 句式写空间关系与动作归属(见下),
```

- BREAK 单独成行;表情动作绝不放进共享区
- 自然语言用 `Place the girl ... while the boy ...` 句式绑定位置+外观+动作;**禁人称代词**(she/he/her/his/they),重复用 the girl / the boy
- 自然语言短句承担:空间布局、动作归属、接触对象、视线引导、剧情状态;放 prompt 末尾

### 3.4 数量控制
- 单人 16-30 tag;双人 22-38;三人 30-48(人数上限 3,不画 4 人及以上)
- 详尽但精炼:覆盖身份/构图/服装/动作/表情所需关键 tag,删弱相关与重复

## 4. 输出契约

最终回复**只含**以下结构,重复 N 次,块与块之间空一行:

```
<image>
<anchor>正文中逐字连续片段,8-30字</anchor>
<prompt>英文tag与自然语言混合的正面提示词</prompt>
</image>
```

- 必须且只输出 N 个 `<image>`;每个恰含 1 个 `<anchor>` + 1 个 `<prompt>`
- anchor 按剧情顺序排列、互不重复、逐字命中正文
- prompt 内不得出现:角色 ID、中文姓名、Markdown、权重语法、质量词、grid/comic 概念、解释文字
- 输出前最后默查:块数 == N?anchor 逐字命中?prompt 无禁物?全部通过才输出
